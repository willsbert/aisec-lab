# D12 纵深防御设计（LLM 应用安全）

依据：D1-D11 全部实验证据（每个措施后标注出处）

## 分层架构

输入层 → 模型层 → 知识层 → 工具层 → 输出层 → 治理层

## 各层措施

### 1. 输入层
- 输入过滤（关键词/正则）：已验证拦直白注入 100%（D9）
- 语义级检测（Llama Guard / Prompt Shield）：补翻译/编码/虚构绕过（D9 漏网 5 条）【待落地】
- 指令与数据强分隔：系统提示词与用户输入隔离（D2 inj-06 教训）
- 限流与配额：防无界消耗（LLM10）

### 2. 模型层
- 安全对齐（RLHF/DPO）：qwen 基线证明有效（D2 直接注入大多被拒）
- adapter 完整性校验：sha256 基线 + 篡改检测（D5 已落地）
- 权重来源审计：只加载可信源模型（LLM03/04）

### 3. 知识层（RAG）
- 文档分级 + 权限过滤：修复 secret.txt 越权（D3/D8 B 靶标泄露实锤）【待落地】
- 检索结果来源标注 + 敏感内容扫描
- 文档/索引可审计可回滚：投毒文档必须清理而非只拦截（D3 持久性教训）

### 4. 工具层（Agent）
- 工具白名单 + 权限矩阵（默认只读，write 需授权）（D6 过度代理教训）
- 高危操作二次确认 / 审批流
- 工具输出与指令隔离：sanitize 消毒（D7 main_hardened 已落地）
- max_steps + 频率/成本配额（LLM10）

### 5. 输出层
- 输出校验：敏感信息/PII 检测（D9"输出已拦截"模式可扩展）
- 日志脱敏（LLM02）

### 6. 治理层
- 威胁建模表 + 定期红队（D7/D10 已产出）
- SBOM + 漏洞扫描闭环（D11 已产出，修复 5 包）
- 监控告警：异常输入-输出映射检测（后门检测思路，D5）

## 设计原则（从实验中提炼）

1. 信任边界：工具输出 / 检索内容永远不视为指令（D6 教训）
2. 最小权限：Agent 默认无 write（D6 过度代理教训）
3. 纵深而非单点：关键词过滤失败 → 语义检测兜底（D9 教训）
4. 安全与可用性平衡：分层策略，一刀切消毒伤可用性（D8 靶标 C 教训）
5. 投毒要清理而非只拦截：文档/索引可审计可回滚（D3 持久性教训）
